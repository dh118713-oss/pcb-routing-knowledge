# 按器件、引脚、网络和区段选择规则

不能从板名“2.4G”、器件大类“无线芯片”或整个板的分类推导最终走线。先建立当前目标的事实，再筛选适用来源。2.4 GHz 是频率，4G/LTE 是通信制式；不同制式可能落在相近频段，同频段也可能有不同芯片、封装、调制、功率和天线要求。

## RF-001：频段、协议、型号和封装分别核对

- **输入：** 器件完整型号和封装、引脚功能、实际RF路径/网络、工作频率范围（Hz）、协议/PHY和配置、参考设计及层叠版本、匹配/滤波/PA/LNA/天线实现。BOM与网表用于器件/引脚定位，频段/PHY由器件与设计配置证明；不从项目名称猜测。
- **动作：** 将芯片能力、系统工作频段、实际协议和板级结构分别比对。每条规则绑定具体目标，不给同芯片的RF口、ADC口、供电口和晶振口复用同一组约束。涉及不同频段/协议/封装的匹配值、几何阈值不能迁移；相同物理回流原理可以作为通用分析入口。
- **已读证据：** `DATASHEET-TI-CC2652R`，SWRS207J pp.1-2（协议、封装、应用）、p.11 §8.9（RF频率2360–2500 MHz）；`DATASHEET-TI-CC1310`，SWRS181D pp.1-2及p.16 §5.5（多个工作频段，包含861–1054 MHz）。两者同属厂商无线平台，支持的RF路径和协议仍不同。
- **判据：** 当前目标事实与已核读资料适用条件一致，器件能力没有冲突；缺少型号/频率/协议/封装证据则保留未知。硅片支持某频段不等于某地区许可发射或整机已通过无线认证。
- **边界：** 本条只建立资料筛选依据；未读完整数据手册，未据此生成匹配元件值、天线尺寸、RF线宽或输出功率设置。CC1310候选条目只登记了其中一个已读频段，排除该条目不等于证明器件不支持其他频段。

## 两步筛选，随后整板协调

1. **机器候选筛选。** `select_rules.py` 比较 [目录](applicability-catalog.json) 的显式条件。输出 `candidate`（已声明条件匹配）、`excluded`（有证据的已知冲突）或 `needs_input`（缺少事实/出处）。不联网、不猜型号、不补参数。
2. **工程适用性复核。** AI 读取候选来源实际章节，核对完整型号/后缀/版本、引脚、封装、参考设计、层叠、工况和例外。候选通过不是最终适用，不是DRC通过，也不授权直接复制数值。未进入目录的规则仍可按同样标准研究，但必须明确“尚无机器筛选条目”，不能默认全库适用。
3. **整板联合审查。** 按 [整板契约](board-review-contract.md) 将各目标约束合并到共享电源、参考结构、热、隔离、RF和工艺冲突图中。一个目标的候选结果不能自动作为另一个目标的事实。冲突需要改变方案或补证据，不能靠多数规则投票解决。

## 事实与对象粒度

`target_id` 建议标出器件实例、引脚/网络与路径段，例如 `U1:RF_P-to-matching`、`U1:VDDS-to-decoupling`、`U2:FB-to-divider`。完整网络需同时满足源端、接收端、负载和沿途器件要求；扇出、主干、支线、连接器和换层段可有不同约束。板级安全/制造/结构约束对所有相关目标继续有效，不能被局部建议覆盖。

每个事实必须包含 `value` 和 `provenance.artifact/locator`。关键事实包括：

| 范围 | 事实示例 |
|---|---|
| 版本 | board_revision、BOM/网表/器件资料/封装图版本 |
| 目标 | component_ref、device_model、package、net_id、net_role、引脚/区段与源/负载 |
| 工作 | technology、frequency_hz、最快边沿、电流波形、温升/压降/噪声/时序预算 |
| 几何 | stackup_revision、相邻参考网络、实际铜形、回流与隔离域 |
| 专项 | reference_design_revision、antenna_implementation、topology、termination、制造装配过程 |

选择器仅检查事实值与出处字段，不打开原始文件、不证明事实真实。调用方须实际提取/核对事实，并将当前目标与不可变工程快照对应。层叠ID存在也不证明层叠正确，具体参数仍由工程复核读取。

## CLI与条件语言

```sh
python scripts/select_rules.py --profile examples/applicability/rf-2g4.json
python scripts/select_rules.py --profile examples/applicability/adc-same-board.json
python scripts/select_rules.py --profile examples/applicability/rf-unknown.json
```

语义使用精确规范化值：`eq` 等值，`in` 标量属于列表，`contains_any` 列表有交集，`range_within` 实际频率范围完整落入声明范围。频率单位统一为Hz；“GHz”不被静默当作Hz。没有出处的值不算已知；缺值与不匹配分开报告。已知不匹配优先排除，不因另有未知字段而重新列为候选。

三个profile都是 **合成演示**，并非任何实际板已完成数据核验。第一例应选中CC2652R RF候选并排除CC1310高段候选；第二例虽在同一合成板上，不能继承U1的RF要求；第三例只有频段信息，必须要求补器件/协议等条件。详见 [示例说明](../examples/applicability/README.md)。

目录是首批经过来源关联的选择条目，尚未覆盖全库工程规则、所有厂商、射频芯片、4G/5G模组或接口。未收录LTE条目就不能声称已自动验证LTE适用性；遇到此对象应获取其实际模块/射频设计资料，再新增经核验的条目。扩充时同步更新目录、来源引用、测试及规则，不编造未知协议数值。
