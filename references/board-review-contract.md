# 整板综合审查契约

同一块板上的器件规则不是彼此独立的清单。每个器件、引脚、网络和关键回路先产生局部约束；然后必须检查它们对共享资源的影响，再对整板重新审查。局部条目全部 `pass` 也不能直接推出整板 `pass`。

这是原创的工程协调契约，不是新物理定律、自动优化器或认证程序。来源可用性和数值可用性分别判断：规则被选为候选，不代表其器件/拓扑/频段已经匹配，更不代表可以落下固定尺寸。只知道功能组合而没有几何、层叠或可用模型时，输出 `planning_state=planning`、`status=unknown`；`planning_state` 不替代接口规定的四种检查状态。

## 1. 约束对象和所有权

每条局部约束都应记录：

- `constraint_id`、`owner`（具体器件/引脚/网络区段/关键回路/电路域/整板对象ID）、可选负责复核角色；
- `rule_ids`、`source_ids`、每条规则对应的原始出处与精确定位、来源状态和适用条件；
- `scope`（器件型号/封装、协议/频段、拓扑、层叠、温度/电流/边沿）；
- `inputs`、单位、假设、证据成熟度和检查方法；
- `strength`：`must`、`recommendation`、`heuristic`；`priority` 只安排工作先后，不能降低已生效硬要求；
- `applicability_status`、必需输入、`dependencies` 与 `gates`：分别说明适用性、依赖对象和达到哪个阶段前需要什么证据；
- 影响的共享资源：层、参考平面、PDN、回流、热扩散、板边/连接器、隔离走廊、可制造区域、测试点和BOM/装配能力。

来源规则拥有自己的适用范围；项目要求、适用标准和器件勘误的硬条件不能被另一个器件的经验建议覆盖。多个建议冲突时保留冲突，不用“加大线宽/再加一个过孔”把未知问题伪装成解决。

适用性未确定时保持 `unknown` 并收集输入；有证据证明不适用时才使用 `not_applicable`。定量判据还须有单位、容差/裕量、工作点和来源；未知值用 `null`，不能以任务优先级、相似器件或候选命中代替这些条件。

## 2. 三层闭环

### A. 器件与关键回路

对每个器件实例识别引脚、去耦、功率/信号回路、封装、推荐层和禁布区域。对同型号不同封装、不同芯片版本、不同电流/边沿和不同层叠重新匹配资料；网络名称和器件类别不能替代型号核对。

**同一个器件也不能套一条统一策略。** 例如 Buck 的 VIN/PGND 属于输入换流路径，SW 是开关节点，FB 是反馈检测，暴露焊盘按实际器件确定电气归属和热作用；它们不能都按“电源脚加粗”处理。ADC 的输入、基准、电源、采样时钟和数字输出分别实例化。芯片集成多个功能时，以引脚角色/工作模式和连接回路选择规则；未知料号只生成角色清单，不编造引脚号。

**同一网络也需要分段。** 扇出、均匀传输段、换层、连接器/保护点和测试支路可能具有不同截面、参考结构或寄生预算；供电主路与高阻检测分支即使网名相同也不能互换几何策略。每段有明确端点、父网络和回路关系；同时保留端到端压降、时序/偏斜、噪声及返回路径预算，不能各段单独用完整预算后相加超限。

输出每个实例的局部约束和缺失输入。例如 2.4 GHz 无线芯片的 RF 规则要绑定具体型号、匹配网络、频段、参考层和天线；同板的其他 4G/5G 或低频模块不会自动继承这些规则。

### B. 电路区域之间的共享资源

建立冲突图，节点包括器件/引脚角色、网络区段、关键回路、电路域，以及具名的共享资源。边分别标明 `shares`（共享）、`couples`（可能耦合）、`depends_on`（依赖）、`conflicts_with`（互斥）和 `must_remain_separate`（电路定义禁止直接连接）。候选耦合边记录“源→路径→受体”、关注频段/工作模式和待验证依据；不能仅凭图中相邻就声称干扰已发生，也不能没有几何就宣称没有干扰。

冲突表每项记录参与约束ID、owner、共享资源、适用硬门槛、候选操作、所需输入/验证、受影响对象、选择理由和恢复条件。图可用表或JSON表达，不要求某个EDA具备内建图功能。至少检查：

| 共享资源 | 典型冲突 | 必须重新检查 |
|---|---|---|
| PDN/电源回流 | Buck 脉冲电流与 ADC 基准、RF 去耦共用阻抗 | PDN路径、共阻抗压降、瞬态、去耦和反馈 |
| 参考平面/层叠 | DDR/SerDes走廊、RF参考层、模拟区和电源平面竞争 | 每段参考层、跨缝、换层返回、阻抗截面 |
| 布线走廊/供电截面 | DDR扇出和等长区域挤压电源铜、颈缩或Buck闭合回路 | 通道拓扑/时序、供电去回压降、温升、过孔/焊盘瓶颈与制造公差 |
| 热扩散铜/过孔 | PowerPAD、MOSFET/稳压器热区靠近晶振、天线或连接器 | 结温/板温、热梯度、RF/时钟耦合、装配可达性 |
| RF禁布/天线环境 | 散热器、屏蔽、连接器或高速线侵入天线净空 | 天线/匹配几何、参考地、外壳和线缆环境 |
| 隔离走廊 | 数字隔离器两侧回流、CAN保护、机壳屏蔽和测试夹具 | 爬电/电气间隙、跨域铜/孔/机械件、共模路径 |
| 制造/装配 | 盲埋孔、钢网开口、QFN中心焊盘与细间距BGA竞争 | DFM/DFA、回流焊、X-ray/ICT、阻抗/铜厚公差 |
| 测试与维护 | 关键节点被RF禁布或散热器遮挡，量产测试点与回流冲突 | ICT/边界扫描/产测、探头加载、返修和替代BOM |

### C. 整板验证与发布门禁

在局部约束执行后重新导出完整板快照，检查冲突图中所有受影响节点和边。只有满足以下条件，才能把某个整板检查记为 `pass`：

1. 当前不可变 PCB/原理图/层叠/机械版本一致；
2. 声明范围内所有适用 `must` 条件已绑定实例并有通过证据；排除项有真实不适用依据，不能仅登记条件就算通过；
3. 共享资源冲突有在现有工程授权内选定的解决方案和证据，适用的未决硬冲突仍会阻止通过；
4. DRC/几何、SI/PI/热/EMC、制造和测试结果按项目所需阶段分别记录，不能互相替代；未完成实测可以得到设计阶段的局部结论，但不能声称已通过样机或生产验证；
5. 受修改影响的检查已重跑，未受影响的检查有版本和依赖证据说明可以复用；
6. `unknown` 不能升级为 `pass`，尤其是未提供层叠、参考平面、热边界、线缆/机壳、制造公差或测试工况时。

修复后沿依赖图传递失效范围：改变参考面可能同时使阻抗、换层回流、PDN和RF模型失效；改变钢网/热铜可能同时影响装配与热验证。依赖关系不足以确定影响范围时，扩大复查或保持 `unknown`。未受影响的结果只在差异分析证明相关输入、工况和模型仍有效时复用；旧报告保留原版本，不把版本字段改成新版本冒充重测。共同工作模式也要纳入，不能仅让Buck、ADC、DDR与RF各自单独运行后推断同时活动的整板通过。

## 3. 冲突解决顺序

1. 按[研究方法](research-method.md)核验要求的真实效力和适用条件。适用硬约束须同时满足；已证明违反的候选排除，未知是否满足的候选保留待验证，不能当可行方案评分；
2. 对已进入可行范围的方案，比较完整回路、PDN、热、阻抗、EMC、装配和测试证据。优先级仅决定求解/处理顺序，不允许“RF优先”或“安全优先”掩盖其它仍未满足的要求；没有共同可行方案时需要布局、层叠、器件、板形或需求变更的真实工程决策；
3. 不能用单一指标（最短、最宽、最多地过孔、最大铜面）或任意数值加权把硬性失败抵消。可在硬约束已满足后，用明确的项目偏好比较非支配候选，并保留取舍及未覆盖项；
4. 若没有求解器/模型/测量支持，返回候选方案和 `unknown`，请求上游工程决策或补证据；
5. 决策记录采用“冲突—候选—依据—取舍—待验证—回退条件”，而不是静默覆盖某条规则。

## 4. 合成混合板示例

假设同板包含 2.4 GHz 无线芯片、Buck、ADC、DDR 和隔离 CAN；DDR代际和所有器件料号都尚未知。结构化的规划示例见 [board-conflicts.example.json](../examples/board-conflicts.example.json)，所有检查为 `unknown`，没有实测或真实几何：

- 无线芯片按具体 CC13xx/CC26xx 或其他实际型号匹配 RF 规则；不能把别的频段、别的封装或别的天线经验移植进来；
- Buck 的高 di/dt 回路与 ADC/RF 电源回流共享 PDN 时，先比较布局和层叠候选，不能仅分别给它们“加粗”和“加去耦”；
- DDR 的拓扑/分组走廊可能与 RF 参考层和电源换层竞争；库中 KeyStone DDR3 指南只在其控制器、存储器和拓扑适用时生效，不因本案例有“DDR”就应用其数值；
- 隔离 CAN 需要同时处理两侧电源/回流、外部线缆、终端和隔离走廊；不能为给高速信号找回流而穿过隔离域；
- PowerPAD/MOSFET 的热铜和热过孔可能侵入 RF 禁布、晶振或连接器区域；热通过不代表 RF/EMC或装配通过。

没有真实器件型号、BOM、层叠、机械边界、连接器/线缆、铜形和工况时，上述只产生规划清单。AI 不应编造固定线宽、净空、过孔距离、层叠或最终生产结论。

## 5. 给 EDA 执行方的接口

```text
局部约束实例化
→ 共享资源/冲突图
→ 候选布局与层叠（记录每个取舍）
→ EDA 执行与铺铜重算
→ 全板快照、DRC和几何证据
→ 受影响局部规则 + 共享资源 + 整板生产门禁复查
→ production-readiness 阶段判断
```

本契约只定义判断结构，不宣称已经实现自动布局、场求解、热求解或整板优化器。实际商用板仍须使用目标 EDA、板厂能力、仿真、样机和试产证据完成发布流程。

配套JSON是规划记录示例，不是已经满足约束执行接口的交付包。示例中的器件、引脚和区段ID只是符号角色；跨匹配/保护元件的通道可以包含多个物理网络，不能据此合并网表。只有绑定实际实例、补齐端点和依赖、确认适用性，再按[集成契约](integration-contract.md)生成并验证正式约束后，才可交给EDA执行。
