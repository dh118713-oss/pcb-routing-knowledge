# 从开源项目学什么

本页是选段查读记录和原创工程归纳，没有复制上游设计文件、图像或实现代码。来源元数据、提交号与许可证记录在 [open-source.json](../sources/open-source.json)。星标数、量产宣传和“开源”身份都不等于电气正确性证明。

## OSS-001：器件条件分支必须保留

来源：[Espressif 官方硬件指南固定提交](https://github.com/espressif/esp-hardware-design-guidelines/tree/caa8ff8402f81b18dfefe4c872e7880cd0566b99)，`docs/en/pcb-layout-design.rst` 的 General Principles、Crystal、RF；源 ID `OSS-ESPRESSIF`。

- **条件与输入：** 使用某个 Espressif SoC/模组时，必须明确具体型号、封装、层叠、射频连接及天线实现。
- **观察：** 原始 RST 含大量 `only`、`list` 和 `IDF_TARGET` 条件；晶振局部净空、距离、RF参考层等会随型号不同。不能把模板默认值视为所有芯片适用的要求。
- **动作：** 对应到具体型号的已渲染指南和引用子文件，核对数据手册/勘误再建立约束。换芯片或层叠时重新求适用值。
- **检查：** 约束必须同时记录芯片型号、指南版本、相关条件分支和几何对象；不能只引用整个仓库首页。天线仍需仿真/实测。
- **范围：** 本次读了选定原文段落，没有完整渲染所有芯片指南和包含文件；不在此提供通用毫米数。

## OSS-002：维护历史能揭示失效模式，不能替代因果验证

来源：[OLIMEX ESP32-PoE 固定提交](https://github.com/OLIMEX/ESP32-POE/tree/deb38a377d50eadb04ddc7118a17a5ae58b1ee53)，`HARDWARE/Revision-changes.txt` 与 M2 PCB 层叠头部；源 ID `OSS-OLIMEX`。

- **案例类型：** `maintainer_report`，是公开维护记录，不是本仓库亲自实测，也不是带误差控制的A/B实验。
- **观察：** Revision I 记录从双层改为四层以改善 DCDC 散热；H1 记录外接负载取电时以太网失联及随后电路修改；M、M1、M2还有电源、接口和兼容性修订。未查到这些选定条目配套的原始温度/EMI波形。
- **动作：** 电源/通信共存板的验收应覆盖外接负载和通信同时运行，必要时验证启动、负载变化、低功耗状态。用失败模式规划测试，不直接复制该板的元件值或层叠。
- **检查：** 本板测试计划有负载条件、通信误码/掉线判据和供电测量点。若比较改版，记录改动变量和环境。
- **限制：** 本次仅静态检查版本说明及PCB局部文本，没有对整板重跑DRC或验证制造层叠；项目文件里的FR4参数不能当实测材料参数。

## OSS-003：必须知道 DRC 到底检查了什么

来源：[KiCad 固定提交](https://github.com/KiCad/kicad-source-mirror/tree/48340549661ce36e91519b7c9fa114a34d8f7f2f)，`pcbnew/drc/drc_test_provider_track_width.cpp` 的 `Run`，差分耦合检查器的约束选择；源 ID `OSS-KICAD`。

- **条件与输入：** 对任何 EDA 的“DRC通过”结论进行审查，需要当前板版本、实际启用规则、豁免/忽略项、检查覆盖和导出结果。
- **观察：** 读到的线宽检查实现遇到没有线宽约束时会跳过测试；有规则时按实际线段/圆弧宽度与层相关判据检查。差分检查还区分间隙和未耦合长度。
- **动作：** 执行方报告具体检查项目及是否启用，而不只返回布尔 `drc_pass=true`。对缺规则、被忽略或工具无法检查的项目输出 unknown。
- **检查：** 回读当前几何与当前规则，核对没有漏检/豁免；阻抗、回流、热和EMC另外评估。
- **限制：** 本次为源码选段查读，没有运行该版本 KiCad；此证据证明检查机制的边界，不证明其他 EDA 实现相同。

## 开源借鉴的入库要求

固定 commit/tag；核验具体文件而非仅README；检查源码/硬件/文档分别使用的许可证；优先保留测试条件、修订与失败记录；引用事实与原创分析。需要复制或改编上游图文/代码时，单独处理其许可证，不用仓库MIT覆盖它。
