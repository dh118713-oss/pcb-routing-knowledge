# 从 PCB 设计到生产发布的证据流程

本文件是原创的项目工程检查模板，用于把 PCB 设计知识接入商用产品的开发、验证和生产准备。它不是从未读书籍或标准摘出的认证程序，没有给出通用量产判据、样本量、试验时间或可靠性保证。具体适用要求、试验方法和合格阈值必须来自本项目已确认的用途、产品规范、器件资料、制造过程和可核查证据。

AI 可以整理要求、提取适用规则、生成设计约束、驱动已有授权下的设计/测试工具、核对记录和发现证据缺口。设计进入下一阶段依赖实际结果；skill 调用成功、DRC 零错误、脚本测试通过或 `audit` 返回证据字段完整，都不能替代生产验证。

本流程与 [集成契约](integration-contract.md)、[研究方法](research-method.md) 和 [板级案例记录](case-record-template.md) 配合使用。生产计划格式示例见 [production-plan.example.json](../examples/production-plan.example.json)；它是带未知项的计划，不是通过报告，当前 CLI 不解析该格式。

## 1. 先建立产品和版本边界

在形成正式设计审查结论前，建立有版本号的需求基线：

- **用途与配置：** 产品做什么、由谁使用、预期安装方式、正常/异常工作模式、线缆/连接器/负载、附件、机壳、固件配置和影响验证的产品变体。
- **市场与适用要求：** 销售/使用地区、产品类别、适用法规和产品/接口/安全/EMC标准的准确版本、适用条款与排除理由。取得对应合法正文或合规团队确认的具体要求；标准标题或书目不能支持某个间距或限值。
- **电气与环境：** 电压范围、连续/RMS/峰值电流、纹波和瞬态、温升与结温/板材限制、时序/噪声/精度、工作/存储温湿度、海拔、污染/凝露、振动/冲击等实际环境，以及寿命和预期使用频率。
- **制造与商业输入：** 预期产量范围、制造/装配路线、板厂/装配厂能力、维修和质量目标、允许公差、可获得器件及可替代范围。
- **验证职责：** 哪些设计、制造、测试和合规职责由已有项目角色承担；哪些外部试验或工程签核确实适用。记录已有授权，不默认每个步骤都需要重新向用户请示。

每条要求记录 ID、提出方/文件及位置、版本、可测判据、单位、验证方法和适用配置。冻结是“本轮采用可追溯基线”，不是永不更改；后续改变应进入变更影响分析。

仅有网表时可完成连通关系及部分器件条件检查。缺少 PCB 几何、真实层叠、实际 BOM 或工作条件时，对相应结果保留 `unknown`，不能用常用值补出“已经验证”的板子。

## 2. 五个阶段与晋级条件

`lifecycle_state` 描述项目当前已取得的证据阶段，不是单项测试结果。按顺序推进，不能由草案直接跳到发布证据齐备。

| 阶段 | 含义与所需证据 | 仍不能推出的结论 |
| --- | --- | --- |
| `design_draft` | 已有需求/方案/约束草案；缺失输入、假设和候选方案明确列出，未取得版本时允许 `board_revision: null` | 不能声称设计或样板已通过；本阶段不要求虚构证据 |
| `design_reviewed` | 需求与适用性基线已建立；原理图/PCB/BOM/相关固件配置绑定版本；设计约束、实际铜形、连通性、DRC、DFM/DFA/DFT和必要模型完成范围内审查；样机验证计划和判据已定义 | 不能声称已完成实物功能、温升、SI/PI、EMC或可靠性验证 |
| `prototype_verified` | 代表计划配置的样机已按定义的电气、热、SI/PI、EMC/安全及其它适用计划验证；环境和可靠性验证达到本阶段要求；测量、失败分析及修正复测可追溯 | 工程手工样板成功不证明制造路线、批次一致性或量产良率 |
| `pilot_verified` | 采用拟用生产路线、材料、装配和产测的试产达到项目判据；重复性、过程缺陷、可靠性验证、返修和批次追溯完成适用检查；工程样板与试产差异已验证 | 不能自动推出无限制批量、所有替代料/变体或所有市场都已覆盖 |
| `release_evidence_complete` | 发布配置/制造包、BOM/许可替代清单、产测与追溯程序、合规证据、剩余事项和适用工程签核记录已齐备；前面各阶段证据仍适用于当前版本 | 不自动下单、上传生产文件、发布认证声明、启动生产或声称获得认证 |

最后状态仅说明**声明产品范围和配置的发布证据包齐备**。如项目需要第三方测试、认证、技术文档或特定职责签核，其真实记录属于相应发布关卡；没有记录就不能写完成。只有在有用户授权或已有有效生产授权、且满足项目实际发布程序时，执行方才可开展相应生产发布动作。

### 单项状态及关卡计算

单项 `status` 沿用 `pass | fail | unknown | not_applicable`。缺输入可在 `reason_code` 写 `needs_input`，缺测量写 `measurement_pending`，不新增第五种结果状态。

- `pass` 需要证据、明确判据、适用配置和有效版本；测了但没有合格阈值不等于通过。
- `not_applicable` 需要说明不适用条件及其证据。仅因缺工具、缺预算、没有测试或“以前没出问题”不能判不适用。
- 目标阶段的任何适用必需关卡为 `fail` 或 `unknown`，均阻止晋级；不能删掉该关卡、改变阈值或改成不适用来隐藏失败。
- 可推迟到后续阶段的检查应在计划中预先标明最晚完成阶段和理由。例如设计审查不需要假造实测，但进入 `prototype_verified` 时适用样机验证不能仍未知。生产发布必需项不能以推迟名义跳过。
- 样本量、批次数、环境组合、加速条件、置信目标及抽样/全检策略，按产品风险、适用规范、变差和制造过程制定并记录理由；本模板不统一规定数字。

## 3. 设计审查：把电气约束和制造条件一起检查

### 电气与结构

从 [电源](topics/power.md)、[模拟与EMC](topics/analog-emc.md)、[高速与RF](topics/high-speed-rf.md)、[基础回流](topics/foundations.md) 选择实际适用的规则。多层板用 [架构清单](topics/multilayer-architecture.md) 展开到这些底层规则；协议或器件未覆盖的部分另取原始资料，不拿相似名称代替。

检查对象至少应覆盖本项目关键回路、供电去回路径、颈缩/过孔、反馈与采样、参考结构、受控阻抗/时序和接口保护。保存计算/模型的温度、材料、层叠、器件模型版本和有效范围。每条约束都要映射到实际几何或其它证据，不能仅证明 EDA 参数已经设置。

### DFM：制造

记录板厂确认的成品层叠、铜厚/蚀刻公差、介质和阻抗能力、钻孔/镀铜/环宽、盲埋孔/背钻、阻焊/表面处理、板形/拼板和可检验性。按实际使用的工艺确定应有的阻抗 coupon、截面、裸板电测和验收数据。

板厂修正、蚀刻补偿、孔型/材料替换或压合变化若影响模型输入，重新核对电气、热和间距结果；“制造可做”不等于满足性能。制造下限和公差来自当前工厂能力及订单，而不是模板默认数字。

### DFA：装配

核对封装/焊盘、引脚方向与极性、BOM/位号/贴装坐标一致性、装配间隙、焊接与检查可达性、热焊盘/过孔处理、钢网和焊接工艺适用性。根据实际器件/过程检查湿敏、温度限制、清洁、涂覆和返修要求。

将设计导致的桥连、虚焊、偏移或装配热问题与实际工艺证据关联，不能仅因参考封装库可选就认为装配完成验证。板厂、装配厂或器件厂建议变化需要记录技术理由与后续验证。

### DFT：可测试性

按故障风险和产品需求定义裸板/装配后/最终功能/校准测试的分工。需要测试点时同时检查探针可达性、供电/返回、治具定位、允许加载、隔离与操作顺序；高速支路、RF、晶振和高阻节点测试点必须评估其电气影响。

定义产测限值与设计限值的关系、测量误差/夹具影响、测试软件/固件版本和失败处理。不能机械为每个网络增加测试点，也不能为改善布线而删除必需的生产故障覆盖。无法直接测量的功能要有可说明的替代观测或检测方案。

## 4. 样机验证：使用当前板子和实际测试条件

验证计划先定义方法、阈值、工况和记录方式，再执行测试。样机应覆盖计划要求的电压/负载/环境/变体组合；条件组合依据项目风险确定，不默认一次室温正常负载测试就足够。

| 验证领域 | 需要取得的实际证据与边界 |
| --- | --- |
| 电气功能与保护 | 供电范围、启动/关闭/时序、正常与相关异常负载、接口功能、保护行为、精度/噪声/校准、稳压与瞬态等适用项；明确静态压降是否含返回、连接器及稳压误差 |
| 热 | 实际损耗/工况、气流/机壳、环境、器件/板材允许温度、测点与测量方法；区分导体温升、壳温和结温。热像发射率、探头扰动和结温推断方法均记录 |
| SI | 按接口/电气长度需求验证时域波形、阻抗、时序/偏斜、眼图/误码或通道参数；记录端口、夹具、带宽、探头与去嵌。只需哪些项目由真实接口要求决定 |
| PI | 关键供电点静态压降、纹波/瞬态及需要的阻抗频域证据；记录源/负载模式、探测位置、带宽、回路连接和有效电容工作点 |
| EMC与安全适用项 | 针对声明市场/产品/使用配置安排要求的发射、抗扰及安全验证；记录线缆、机壳、接地、固件模式、等级和验收依据。预扫/近场检查用于定位，不能替代要求的正式报告 |
| RF/无线专项 | 仅在适用时检查目标频段、输出/谐波/匹配、天线与机壳/电池配置及有关正式要求；芯片或模块已有证书不自动证明最终整机适用 |

失效必须保留原始记录、可复现步骤、根因或剩余不确定性、修正差异及复测结果。改变布线后不能仅重跑 DRC 就沿用旧 EMI 或热结论；模型预测、外部文献实测和本地样机实测分别记录。

## 5. 可靠性与试产：验证可重复生产

依据真实使用环境、寿命和失效风险制定可靠性计划；温湿度、循环、机械、连接器寿命、腐蚀/凝露或其它项目只在适用时纳入。加速因子及寿命外推需有可核验模型和适用域，不能把若干小时加速试验直接写成若干年寿命。试验前后判据、样品身份、暴露条件、失效/返修和数据完整性均保留。

试产采用拟用供应链与生产路线，核对工程样板和量产工艺差异：板材/叠层、铜厚、工厂/产线、焊接/清洁/涂覆、钢网/治具、BOM、软件/固件、线缆/外壳、校准和产测。每项差异有影响分析，必要项完成再验证。

收集项目定义的良率、缺陷分类、返修、重复测量及工艺变差证据；产测方法需证明对目标故障具有所需检测能力，并评估误放、误拒和测量不确定性。不能把单块样板通过当作批次稳定。过程指标、样本量和接受界限按项目计划确定，不由本 skill 擅自套用统计阈值。

## 6. 发布包、BOM替代和追溯

发布包至少能把设计、实物和测试记录互相定位：

- 原理图、PCB、网表、BOM、完整层叠、Gerber/ODB++等实际采用的制造输出、钻孔/贴装/装配图及必要工艺说明，均有受控版本和文件清单。
- BOM 记录精确料号/封装/额定和关键工作点；允许替代不是“同数值即等效”。按替代涉及的偏压容量、ESR/ESL、开关边沿、热性能、尺寸、时序等实际差异进行影响分析，并完成适用复测。
- 固件/可编程器件内容、配置、校准方法/数据、产测脚本、治具/仪器版本及测试限值与发布配置绑定。设备序列号/批次、器件/裸板/装配批次的追溯深度按风险和合同确定。
- 留存制造/装配反馈、裸板和成品测试记录、外部报告、可靠性/试产结论、失败与纠正记录，以及项目实际要求的工程签核/合规文件。
- 定义生产异常隔离、返修/复测、变更通知和现场失效反馈流程；发现当前结论依赖的假设不成立时，重新打开相应关卡。

完整证据包不是下单授权。是否发制造文件、购买器件、安排试产、签署文件或发布生产版本，按用户授权和项目已有职责执行。已授权范围内的信息核查、报告整理和可逆设计工作持续推进，不设置逐步用户审批。

## 7. 证据失效与重新验证

每条证据至少标明文件/记录定位、不可变设计/BOM/固件配置、样品/批次身份（若适用）、验证方法、工况、判据、测量/模型结果、误差或限制，以及执行/复核记录。更细的仪器/探头/校准字段见 [案例模板](case-record-template.md)。

当改变需求/市场、器件/BOM替代、层叠/材料/铜厚、布局/走线/过孔、机壳/线缆/散热、固件活动模式、板厂/装配路线或产测流程时：

1. 生成新版本并列出具体差异，判断受影响的要求、模型、测试和生产过程；
2. 将依赖旧假设的关卡重新标为 `unknown`，保留旧证据的真实版本和历史结论；
3. 对不受影响的证据，仅在有可审查的差异/等效性理由时复用，不复制修改其版本字段；
4. 完成适用的重新计算、设计审查、样机或试产验证后，再按阶段恢复结论。

当前 `lifecycle_state` 必须退回仍由有效证据支持的最早受影响阶段之前；历史里程碑保留为历史，不冒充新版本状态。例如只有产测工装变化且设计/样机证据经影响分析仍有效，可保留 `prototype_verified`，重新打开试产和发布关卡；若关键回流几何改变使设计审查不再成立，则回到 `design_draft`。

本仓库的本地工具测试只能验证脚本行为和文档结构。它们不会自动推进上述生产阶段，也不证明任何实际产品满足商用量产要求。
