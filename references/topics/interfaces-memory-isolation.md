# 存储器、外部总线与数字隔离

本页把接口资料转换为工具无关的输入、动作和检查项，供布局布线执行器调用。来源详情见 [厂商来源台账](../sources/vendor.json)。页码均指 PDF 文件页码；本页的 TI KeyStone DDR3、经典高速 CAN 和 TI 数字隔离器示例不能代替其它器件或协议版本的规范。与 [高速互连](high-speed-rf.md)、[多层板架构](multilayer-architecture.md) 和 [模拟与 EMC](analog-emc.md) 联合使用。

检查结果使用 `pass`、`fail`、`unknown`、`not_applicable`。缺少适用器件、拓扑、接口版本、外部线缆或隔离要求时，只能给出待补输入及条件化建议；不能把 DRC、连通或几何等长当作接口合格证据。

## INT-001：先确定完整接口，再实例化布线约束

- **条件／性质：** 存储器、外部总线或带数字隔离的接口；输入完整性门槛。
- **输入：** 协议及版本、控制器和 PHY／收发器完整型号与封装、器件修订及勘误、数据率和最快边沿、I/O 电压、节点／rank 数量、拓扑、层叠、终端与保护、封装／连接器／线缆，以及目标时序和噪声预算。
- **动作：** 区分逻辑协议、物理层、板内互连与外部介质；建立从发送端到接收端的完整路径和器件版本清单。按网络角色加载约束，记录每个参数对应的适用指南和项目输入。
- **检查方法：** 将原理图、器件表、布线分组和外部连接逐一对应；指出缺失的模型、版本和未知路径。用边沿及传播延迟评估电长度，不能仅按时钟或比特率判定是否为高速。
- **来源与定位：** `VENDOR-TI-SPRABI1` p.6 §4、pp.9-10 §4.7；`VENDOR-TI-SLLA272` pp.1-3 §§2-6；`VENDOR-TI-SLLA270` pp.5-11 §4；`VENDOR-TI-SLLA284` p.8 §3.1。
- **限制：** RS-485 是电气层标准，不定义完整通信协议；数字隔离器本身也不保证上层接口时序。输入不完整时不得套用相近接口名称或默认差分阻抗。

## INT-002：DDR 拓扑必须匹配控制器、存储器与训练方式

- **条件／性质：** DDR 存储接口；器件与代际相关的拓扑约束。已核读示例范围为 TI KeyStone DDR3。
- **输入：** 控制器和 SDRAM 型号、代际、离散器件／UDIMM、rank 和位宽、地址／命令／控制／时钟／数据分组、读写 leveling 与 ODT 支持、连接顺序及封装延迟。
- **动作：** 按适用硬件指南分别确定各类信号的拓扑。对 SPRABI1 覆盖的 fly-by 方案，地址／命令／控制／时钟按规定顺序经过各 SDRAM；数据按规定 byte lane 及 rank 拓扑连接。布局先保留拓扑需要的器件顺序和通道，再进行布线。
- **检查方法：** 从控制器焊盘追踪实际分支和负载顺序，检查多余支路、错误星形／T 形连接、组归属及与初始化／训练配置的对应。不能只比较每根线的总长度。
- **来源与定位：** `VENDOR-TI-SPRABI1` pp.3-4 §3.1、pp.14-17 §§6.2-6.3.1、pp.18-20 §§6.3.1.4-6.3.1.7。
- **限制：** 不推出“所有 DDR 都必须 fly-by”或“所有数据都能任意点到点”。不得直接迁移到 LPDDR、DDR4／DDR5 或其它控制器；拓扑和 pin swap 均需其专用指南支持。

## INT-003：DDR 分组检查电气延迟、支线与过孔

- **条件／性质：** 已确定拓扑的 DDR 接口；按组和路径段实例化的约束。
- **输入：** byte lane 的 DQ／DM／DQS 对应表、地址／命令／控制组、各 CK 差分对、逐负载路径段、目标阻抗及偏斜、封装延迟、层叠、过孔与支线模型。
- **动作：** 分别约束 DQ 相对对应 DQS、DQS 对内、CK 对内及地址／控制相对时钟的关系；fly-by 逐段／逐负载检查，不能仅末端等长。保持适用规则要求的参考平面与换层一致性，减少非必要残桩和长支线。
- **检查方法：** 报告每组总路径、分段路径、实际传播延迟、参考层、过孔结构及支线。对缺少封装或传播参数的结果标明仅完成几何检查；相同过孔数量不能替代过孔结构和电气延迟比较。
- **来源与定位：** `VENDOR-TI-SPRABI1` pp.15-20 §6.3.1，特别是 Tables 6-2 至 6-6。
- **限制：** 该示例的 50 Ω 单端、100 Ω 差分、地址／控制支线小于 80 mil、时钟支线小于 40 mil，以及特定 mil 偏斜和过孔数要求，只能在其适用平台重新确认后使用。资料 p.20 的部分文字存在缺数字／表述简略，不能据此自动生成参数；本页不把这些值设为通用默认。

## INT-004：DDR 终端、ODT 与 VTT 按完整拓扑验证

- **条件／性质：** DDR 外部终端或片内终端；器件专用连接与 SI／供电联合约束。
- **输入：** 读写方向、rank、leveling、ODT／驱动强度配置、终端网络与 VTT／VREF 要求、负载及封装／走线寄生、上电和运行工况。
- **动作：** 按目标控制器指南区分地址／控制、时钟与数据的终端方式。对适用 fly-by 外部并联终端，将其放在规定的线路末端并控制末端连接；将终端值、ODT 状态、驱动强度和实际寄生一起仿真。检查 VTT 的跟踪与供电能力，不能把终端电源任意等同于地。
- **检查方法：** 检查终端相对于最后负载的位置、连接支线、返回与电源；对读写及不同负载组合验证振铃、过冲／欠冲、时序和电源表现。若拟省略指南中的外部终端，必须保留适用指南许可与完整模型的证据。
- **来源与定位：** `VENDOR-TI-SPRABI1` pp.14-15 §6.2，尤其关于末端位置及包含全部寄生的仿真要求；pp.9-10 §4.7。
- **限制：** 不搬用该文的 39 Ω、VDDQ/2、500 mil 或具体时钟终端电路到其它控制器。原文中 VTT 生成和时钟终端的描述不能代替目标器件电源设计指南，也不支持任意用无缓冲分压器给实际终端负载供电。

## INT-005：RS-485 终端与支线按边沿及介质确定

- **条件／性质：** RS-485 总线，包括 PCB 到外部线缆的完整连接；总线级物理层约束。
- **输入：** 半／全双工、驱动器最快边沿、节点／单位负载、主干和支线长度、各介质传播延迟及阻抗、连接器、终端、failsafe 偏置、保护和共模预算。
- **动作：** 明确主干、物理末端和各节点支线；按适用方案匹配终端与传输线阻抗，避免每个节点都并接终端。支线预算包含连接器到收发器的 PCB 段和外部支路。采用分裂终端时联合考虑电阻匹配、返回点和噪声转换；同时校核偏置与终端的总负载。
- **检查方法：** 计算主干与各支线的传播延迟，比较最快边沿并用模型／测量验证反射在采样前的衰减；检查每种接线和节点断开状态下的终端、共模范围及接收裕量。
- **来源与定位：** `VENDOR-TI-SLLA272` pp.1-5 §§3-9，尤其 p.3 §6 和 pp.4-5 的偏置／加载讨论。
- **限制：** 120 Ω 是文中典型线缆及终端条件，不能强制所有板内线段使用同样截面。文中“支线传播时间小于驱动上升时间的 1/10”是其设计准则；用于初筛时须注明单程传播时间、速度和边沿定义，并通过项目模型确认，不产生通用毫米上限。

## INT-006：CAN 同时审查拓扑、节点负载和往返时延

- **条件／性质：** CAN 物理层；已核读来源为 2008 年的经典高速 CAN 指南。
- **输入：** CAN 版本和仲裁／数据阶段速率、控制器 bit timing 与时钟误差、收发器及隔离器延迟、线缆传播、主干／支线、节点分布和差分电容、终端／split termination、连接器和防护器件模型。
- **动作：** 把线路两端终端和每个节点支线纳入总线图；把隔离器、收发器、线缆和控制器相关延迟纳入适用的往返时序预算。根据节点电容与间距评估阻抗扰动；split termination 的电阻匹配、电容和返回路径依据目标设计验证。
- **检查方法：** 对最远节点、最短／最长支线及节点数量变化计算时延和反射，检查采样点及重同步预算。核查终端是否会随可拔节点移除，并检查保护器件／共模器件引入的电容、不平衡和故障条件。
- **来源与定位：** `VENDOR-TI-SLLA270` pp.5-11 §§4.1-4.11，尤其 pp.9-10 的 stub 与隔离延迟、p.11 的节点电容。
- **限制：** 其 120 Ω、0.3 m 支线、临界长度比例、4.7 nF 或样例传播延迟不是 CAN FD／CAN XL 的规则。原文 split termination 处把滤波频率写作 Mbps 等表述不能直接用于计算；本页保留审查结构，数值以当前器件和适用接口规范为准。

## INT-007：外部总线的参考、屏蔽和隔离要联合决定

- **条件／性质：** RS-485／CAN 跨板、远端供电或处于明显地电位差的系统；系统架构约束。
- **输入：** 各节点电源与保护地／机壳／信号地关系、预期地电位差、共模瞬态与浪涌、收发器共模能力、线缆屏蔽、连接器和隔离电源方案。
- **动作：** 追踪信号参考、保护泄放、屏蔽和供电的完整路径，判断是否需要信号及电源隔离。将隔离两侧视为不同电气域；根据低频地环路、高频回流和产品要求选定屏蔽连接与防护返回方案，再交给布线器实施。
- **检查方法：** 检查所有铜、屏蔽、安装件、调试接口和电源是否意外桥接隔离域；计算／测试远端地偏移和瞬态时的收发器共模与保护电流。没有线缆／机壳输入时，不给出系统 EMC 通过结论。
- **来源与定位：** `VENDOR-TI-SLLA272` pp.6-7 §11；`VENDOR-TI-SLLA270` pp.6、10 §§4.3-4.4、4.9；`VENDOR-TI-SLLA284` pp.7-8 §§2-3.1。
- **限制：** SLLA270 的单点地／屏蔽 pigtail 建议反映其情境和年代，不能覆盖高频屏蔽要求。不能自动统一为屏蔽单端或双端接地，也不能为改善回流擅自添加跨隔离电容、地过孔或机壳短接。

## INT-008：隔离边界必须覆盖所有层和机械导体

- **条件／性质：** 数字隔离器或类似跨域器件；由适用安规和器件资料决定的禁布与绝缘约束。
- **输入：** 隔离域和工作／瞬态／浪涌电压、基本／加强绝缘要求、适用产品标准、污染等级、材料 CTI／组别、海拔、封装与焊盘、PCB 槽、涂覆和制造公差。
- **动作：** 依据器件与标准建立跨域隔离走廊，检查全部层；在 SLLA284 所示隔离器下方保持规定的平面、走线、过孔和焊盘禁布区。需要槽时，按适用标准验证槽宽、深度、有效爬电路径及机械强度。
- **检查方法：** 分别测量沿表面的爬电距离和穿空气的电气间隙，检查内层导体、覆铜、阻焊开窗、金属紧固件、散热器、屏蔽和污染路径；不能只看顶层焊盘距离。缺少实际几何或标准条款时标记 `unknown`。
- **来源与定位：** `VENDOR-TI-SLLA284` p.8 §3.1、pp.10-11 §§4.2-4.3，Figs.4-1 至 4-2。
- **限制：** 应用笔记不是完整安规标准；“大于 1 mm 的槽”及其路径示意不能替代产品标准计算，也不意味着槽必然改善空气间隙。是否允许跨域安全电容或特殊内层结构必须有专用设计依据，布线器不能自行取消禁布区。

## INT-009：隔离器各侧分别维护回流、去耦与时序

- **条件／性质：** 数字隔离器两侧的高速数字与电源连接；局部 SI／PI 约束，服从隔离边界。
- **输入：** 器件通道、输入／输出电气模型、传播延迟和通道偏斜、CMTI、供电及去耦要求、各侧参考层与层叠、信号电长度、开关噪声和电源瞬态。
- **动作：** 分别在各自隔离域内缩短信号和局部去耦回路，维持连续参考平面并减少不必要换层；需要换层时提供同域返回连接。根据实际边沿、驱动阻抗和互连模型决定受控阻抗或源端匹配，不能默认全部隔离器输出为 50 Ω。
- **检查方法：** 核查去耦与供电引脚的实际闭合回路、过孔与平面空洞，计算通道／往返延迟对 SPI、时钟／数据或控制环路的影响；结合电源噪声与共模瞬变验证误码／毛刺和时序。
- **来源与定位：** `VENDOR-TI-SLLA284` p.8 §3.1、pp.10-18 §§4.2、4.4-4.8。
- **限制：** 该文四层结构、3W、每端两个过孔及示例阻抗是其条件下的建议，不是所有隔离板的最低层数或固定几何值。不得为满足回流而跨越隔离走廊连接两侧地；CMTI、耐压、工作电压和传播延迟是不同指标。

## INT-010：接口审查结果必须带验证范围与剩余风险

- **条件／性质：** 本页所有接口约束的输出和交付；证据分级门槛。
- **输入：** 已实例化的规则、来源版本、原理图及 PCB 几何、模型与计算、制造数据、测试方法、工况和验收预算。
- **动作：** 分开输出输入完整性、连接／几何检查、模型验证、板级测量和系统测试结果；列明每项通过所支持的范围。按接口需要选择 SI／PI、TDR、眼图／时序／误码、总线最坏节点通信、ESD／EMC、共模瞬变及绝缘测试，不把所有测试机械施加到每个接口。
- **检查方法：** 每个结论记录对象、条件、工具／仪器、输入和结果；仿真与实测明确区分。没有相应证据时输出 `unknown` 与所需下一步，而不是因 DRC 或普通通信成功就升级为协议／安规合格。
- **来源与定位：** `VENDOR-TI-SPRABI1` p.6 §4.1、pp.14-15 §6.2；`VENDOR-TI-SLLA272` pp.3-7 §§6-11；`VENDOR-TI-SLLA270` pp.9-11 §§4.8-4.11；`VENDOR-TI-SLLA284` p.8 §3.1、pp.10-18 §4。本条证据分级与结果格式是本知识库的工程综合要求，所列资料不构成这些测试的完整规范。
- **限制：** 本页可生成审查与修正建议，不能自行出具 USB／Ethernet／DDR 协议认证或产品安全认证。当前没有覆盖 Ethernet、LPDDR、完整 USB 认证、全部 DDR 代际、CAN FD／CAN XL 专用设计和各产品安规标准；遇到这些范围应加载新的一手资料后再实例化约束。
